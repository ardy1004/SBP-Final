## Gotcha Wajib Diingat
- **✅ SUDAH DI WORKERS PAID sejak 2026-08-01 — batas 10 ms CPU TIDAK BERLAKU LAGI.** Akun sudah upgrade ($5/bln), batas CPU naik 10 ms → 30 detik. **Jangan lagi menolak fitur, menyarankan prerender/SSG, atau mendiagnosis Error 1102 dengan alasan batas CPU FREE.** Nol perubahan kode diperlukan saat upgrade — batas CPU itu level akun dan langsung berlaku ke deployment yang sudah live (Pages Functions ikut plan Workers).
  - Verifikasi setelah upgrade (colo CGK): `npm run smoke` default **0/320**, `--cached` **0/320**, dan login (`bcryptjs` cost 12 = **233 ms CPU**) tuntas 401 dalam ~0,8 s. Yang terakhir itu bukti POSITIF, bukan sekadar "tidak terlihat gagal": jalur 233 ms mustahil selesai di bawah cap 10 ms.
  - **Pemicu keputusannya**: login 503. Diukur — bcrypt cost 12 = 233 ms (23× batas lama), cost 10 = 58 ms, PBKDF2 native 210k = 71 ms, 100k = 35 ms. **Tidak ada algoritma hashing password yang aman muat di 10 ms** — hashing password memang dirancang lambat. Menurunkan cost factor demi muat = melemahkan keamanan sistem yang menyimpan NIK; jangan lakukan.
  - **JANGAN bongkar mitigasi yang sudah ada** karena merasa sudah lega: cache edge tetap membuat situs cepat & hemat, dan anggaran bundle tetap aturan ratchet (lihat di bawah).
  - *Sejarah yang masih berguna (jangan dihapus)*: dulu batas ini sempat salah didiagnosis sebagai batas *startup*/ukuran bundle, dan berjam-jam habis mengecilkan bundle tanpa menyelesaikan. Uji pembeda yang menutup perdebatan (2026-07-26, konkurensi 12, tanpa cache): `/robots.txt` (non-Worker) gagal **0%**, `/admin/login` **13%**, `/privacy` (statis) **73%**, `/` **85%** — semua di Worker yang sama. Yang menentukan **berat render**, bukan startup. Pola diagnostik itu tetap relevan bila suatu saat muncul kegagalan berkedip lagi.
  - **Error 1102 masih mungkin muncul karena sebab AMBIENT** (kapasitas colo Cloudflare), bukan lagi karena plan. Kalau smoke tiba-tiba gagal: smoke URL deployment LAMA (`https://<hash>.sbp-final.pages.dev`) berdampingan dengan yang baru — kalau kode lama yang tak disentuh ikut gagal, itu ambient, bukan regresi.
- **Cache edge WAJIB lewat Cache API, bukan header `Cache-Control`** — Worker berjalan **sebelum** cache CDN, jadi menyetel `Cache-Control` saja TIDAK mencegah Worker dieksekusi ulang dan tidak menolong sama sekali terhadap batas CPU. Helper tunggal: `functions/_lib/edgeCache.js` (`withEdgeCache`), dipakai `[[catchall]].js` (TTL 300 s), `sitemap.xml.js` & `llms.txt.js` (TTL 3600 s).
  - Aturannya **allowlist**: `NEVER_CACHE_PREFIXES = /admin, /api, /sign, /titip-jual`. **`/sign` merender NIK terdekripsi — jangan pernah keluarkan dari daftar itu.** Request bercookie `sbp_session` juga di-bypass. Param pelacak (`utm_*`, `fbclid`, dst) dibuang dari cache key, kalau tidak trafik iklan Meta = 0% hit rate.
  - Debug lewat header respons `X-SBP-Cache`: `HIT`/`MISS`/`SKIP`/`BYPASS`/`OFF`.
  - Hasil terukur di produksi: URL berulang **0/320 gagal**, URL unik (selalu miss) **31/320**, sebelum cache **69/320**.
- **Setiap route admin baru WAJIB lewat `clientOnly()`** (`src/app/lib/clientOnly.tsx`) dengan wrapper tipis di `src/app/routes/admin/*.tsx` — jangan tunjuk komponen admin langsung dari `routes.ts`. Fallback-nya (`AdminPageSkeleton`) harus **deterministik**: dilarang `Date.now()`, `Math.random()`, `window`, `localStorage`, atau format bergantung locale, kalau tidak muncul hydration mismatch.
- **⚠️ `.gitignore` ikut dibaca pemindai `@source` Tailwind v4.** `src/styles/tailwind.css` memakai `@import 'tailwindcss' source(none)` + `@source '../**/*.{js,ts,jsx,tsx}'`, dan Tailwind menerapkan aturan `.gitignore` pada pemindaian itu. Pola **brace tak berpasangan** (`*{`, `*}`) membuat scanner tidak menemukan satu pun kelas → CSS runtuh dan situs tampil **tanpa gaya**. Terjadi 2026-07-27: CSS produksi 128.021 B → 13.018 B.
  - **Yang paling berbahaya: semua gate hijau.** `npm run build` exit 0 (Tailwind sukses, hasilnya saja kosong), `check:bundle` LULUS (dulu hanya mengukur JS), `smoke` 0/320 (halaman tetap 200, cuma tak bergaya). Rusaknya hanya terlihat oleh mata.
  - Terbukti lewat bisect: **brace merusak, kurung biasa `*(`/`*)` tidak** — makanya pola lama `(a` dan `[0-9])` selama ini aman.
  - Sekarang dijaga `assertCssTerbangun()` di `scripts/check-bundle-budget.mjs`: lantai 80.000 B + wajib memuat `.flex`/`.grid`/`.rounded`. Jangan menurunkan lantai itu untuk "menghijaukan" build — selidiki penyebabnya.

- **⚠️ Menulis skrip Node yang memanggil `wrangler d1` — 4 jebakan, semuanya sudah memakan waktu:**
  1. **`--file` TIDAK mengembalikan baris data**, hanya RINGKASAN (`Rows read`). Untuk SELECT **wajib `--command`**. Memakai `--file` untuk baca membuat skrip melaporkan **1 baris dari 533** dan seluruh statistik dry-run tampak hijau di atas data sampah.
  2. **`--command` kena `ENAMETOOLONG`** untuk UPDATE besar (batas argumen Windows ~32 KB). Jadi aturannya: **baca lewat `--command`, tulis lewat `--file`.**
  3. Memanggil `npx`/`npx.cmd` via `execFileSync` di Windows/Node 24: tanpa shell → `EINVAL`, dengan `shell:true` → argumen dipecah di setiap spasi sehingga SQL rusak. Jalan bersih: panggil `node_modules/wrangler/bin/wrangler.js` langsung dengan `process.execPath`, tanpa shell.
  4. `out.indexOf('[')` untuk memotong JSON keluaran **salah** — banner wrangler memuat `[` lebih dulu. Pakai `out.match(/\[\s*\{\s*"results"/)`.
